# 1 Теоретические сведения

## 1.1 Графы и способы представления

Граф — математическая структура `G = (V, E)`, где `V` — множество вершин, `E` — множество рёбер. Рёбра могут быть ориентированными или неориентированными, взвешенными или невзвешенными. В данной работе используется ориентированный взвешенный граф.

Table: Таблица 1 — Способы представления графа

| Представление | Память | Проверка наличия ребра | Перебор соседей | Когда удобно |
|---|---:|---:|---:|---|
| Матрица смежности | `O(V^2)` | `O(1)` | `O(V)` | Плотные графы, быстрые проверки |
| Список смежности | `O(V+E)` | `O(deg(v))` | `O(deg(v))` | Разреженные графы, обходы |
| Список рёбер | `O(E)` | `O(E)` | `O(E)` | Простая реализация, алгоритмы на рёбрах |
| Матрица инцидентности | `O(V*E)` | `O(E)` | `O(E)` | Редко, теоретические задачи |

В реализации выбран список рёбер: граф небольшой, структура проста для ввода, вывода и перебора исходящих рёбер.

## 1.2 Кратчайший путь во взвешенном графе

Кратчайший путь между вершинами `s` и `t` — путь минимальной суммарной стоимости рёбер среди всех допустимых путей из `s` в `t`. Для графов с неотрицательными весами корректны алгоритмы Дейкстры, а также переборные методы с отсечением. При отрицательных весах используются алгоритмы Беллмана–Форда или Флойда–Уоршелла (при отсутствии отрицательных циклов).

## 1.3 Метод построения дерева решений

Метод построения дерева решений в задаче поиска кратчайшего пути можно рассматривать как поиск в пространстве состояний с отсечениями (ветви и границы). Каждое состояние — частичный путь из источника в текущую вершину.

- **Корень** — начальная вершина, стоимость `g = 0`.
- **Ветвление** — переход по исходящему ребру в вершину, которая ещё не входит в текущий путь.
- **Лист-цель** — достигнута целевая вершина.
- **Лист-тупик** — нет допустимых продолжений.
- **Отсечение** — если текущая стоимость `g` не меньше стоимости лучшего найденного полного пути `best`, ветвь отбрасывается.

При неотрицательных весах отсечение корректно: любое продолжение пути имеет стоимость `g + w_extra >= g >= best`, поэтому улучшить текущее лучшее решение оно не может.

# 3 Реализация

## 3.1 Представление графа

Граф хранится как число вершин и список ориентированных взвешенных рёбер.

::: {custom-style="ListingCaption"}
Листинг 4 — Структура ребра и класс графа (фрагмент `include/graph.hpp`)
:::

```cpp
struct Edge {
    int from = 0;
    int to = 0;
    int weight = 0;
};

class Graph {
public:
    explicit Graph(int vertexCount);
    void reset(int vertexCount);
    bool addEdge(int from, int to, int weight);
    std::vector<Edge> outgoing(int from) const;
    void printAdjacency(std::ostream& out) const;
    // ...
};
```

Метод `addEdge` проверяет корректность номеров вершин, неотрицательность веса и отсутствие дубликата ребра `from -> to`. Метод `outgoing(from)` возвращает исходящие рёбра, отсортированные по номеру вершины-получателя, что делает дерево решений детерминированным.

## 3.2 Алгоритм поиска кратчайшего пути

Класс `DecisionTreeShortestPath` строит дерево решений в виде списка узлов `DecisionNode`. Каждый узел содержит вершину, накопленную стоимость `g`, индекс родителя, глубину и статус (цель, отсечение, тупик).

::: {custom-style="ListingCaption"}
Листинг 5 — Псевдокод метода построения дерева решений
:::

```text
ПОИСК_ДЕРЕВОМ_РЕШЕНИЙ(graph, source, target):
    bestCost = +∞; bestPath = НЕ_НАЙДЕНО
    стек = { (source, g=0, path=[source]) }

    пока стек не пуст:
        (v, g, path) = снять со стека
        если best найден и g >= bestCost: отсечь; продолжить
        если v == target:
            если g < bestCost: обновить best; продолжить

        candidates = исходящие рёбра v в вершины, не входящие в path
        если candidates пуст: тупик; продолжить

        для каждого ребра (v -> u, w) в candidates:
            ng = g + w
            если best найден и ng >= bestCost: отметить отсечение
            иначе положить (u, ng, path + [u]) в стек

    вернуть bestPath
```

В реализации используется стек (DFS), при этом потомки кладутся в стек в обратном порядке номеров вершин-получателей. Это обеспечивает детерминированный порядок обхода: вершина с меньшим номером рассматривается раньше.

## 3.3 Пошаговый разбор на предложенном графе

Рассмотрим поиск пути из вершины 1 в вершину 6.

1. Корень: `(1, g=0)`, `best = +∞`.
2. Из 1 доступны 2 (`g=8`) и 3 (`g=4`); раскрываем ветви.
3. Ветвь через 3 даёт кандидатов 2 (`g=7`), 4 (`g=6`), 6 (`g=14`).
4. Ветвь `1-3-2` даёт 4 (`g=13`) и 5 (`g=10`).
5. Ветвь `1-3-4` даёт 5 (`g=9`) и 6 (`g=7`).
6. При достижении `1-3-4-6` получаем `best = 7`.
7. После этого все состояния с `g >= 7`, не ведущие к улучшению, отсекаются; ветвь `1-2` также даёт потомков с `g >= 7` и отсекается.

Итог: кратчайший путь `1 -> 3 -> 4 -> 6`, суммарный вес `7`.

## 3.4 Сравнение алгоритмов кратчайшего пути

Вариант 3 использует метод построения дерева решений. Для понимания места этого метода среди других алгоритмов приведено сравнение.

Table: Таблица 5 — Сравнение алгоритмов поиска кратчайших путей

| Алгоритм | Задача | Ограничения на веса | Типичная сложность | Идея | Особенности |
|---|---|---|---|---|---|
| Дерево решений / ветви и границы | Кратчайший путь `s -> t` | Для отсечения — неотрицательные | В худшем случае экспоненциальная | Перебор путей с отсечением по лучшему решению | Нагляден, удобен для малых графов |
| Дейкстра | Пути от `s` до всех | Неотрицательные | `O((V+E) log V)` | Жадный выбор вершины с минимальной дистанцией | Эффективен на больших графах |
| Беллман–Форд | Пути от `s` до всех | Допускаются отрицательные, без отрицательных циклов | `O(V*E)` | Релаксация рёбер `V-1` раз | Обнаруживает отрицательные циклы |
| Флойд–Уоршелл | Пути между всеми парами | Допускаются отрицательные, без отрицательных циклов | `O(V^3)` | Динамика по промежуточным вершинам | Удобен для плотных малых графов |
| Йен | `K` кратчайших путей `s -> t` | Обычно неотрицательные | Зависит от `K` и подалгоритма | Последовательный поиск альтернативных путей | Нужен, когда важны несколько маршрутов |

# 5 Ответы на контрольные вопросы

## 5.1 Что такое граф?

Граф — структура `G = (V, E)`, состоящая из множества вершин `V` и множества рёбер `E`. В ориентированном графе ребро имеет направление, во взвешенном — числовой вес. Графы моделируют сети, маршруты, зависимости и другие отношения между объектами.

## 5.2 Какие способы представления графа существуют?

Основные способы: матрица смежности, список смежности, список рёбер, матрица инцидентности. Выбор зависит от плотности графа, требуемых операций и ограничений по памяти. В работе выбран список рёбер как простой и достаточный для малого ориентированного взвешенного графа.

## 5.3 Что такое дерево решений в задаче кратчайшего пути?

Это дерево состояний поиска, где корень — начальное состояние, узел — частичный путь, ветвь — выбор следующей вершины, а лист — достижение цели, тупик или отсечённое состояние. Такой способ делает перебор наглядным и позволяет отсекать заведомо неоптимальные ветви.

## 5.4 Почему отсечение корректно при неотрицательных весах?

Если текущая стоимость частичного пути `g >= best`, то любая его достройка имеет стоимость `g + w_extra >= g >= best`, так как `w_extra >= 0`. Следовательно, в этой ветви нет более короткого полного пути до цели.

## 5.5 Чем метод дерева решений отличается от алгоритма Дейкстры?

Дейкстра поддерживает минимальные известные расстояния и жадно раскрывает вершины в порядке возрастания дистанции, работая за полиномиальное время при неотрицательных весах. Метод дерева решений перебирает пути в пространстве состояний и может рассматривать одну вершину в разных ветвях; он нагляден, но в худшем случае имеет экспоненциальную сложность.

## 5.6 Что будет при отрицательных весах?

При отрицательных весах отсечение `g >= best` может стать некорректным, потому что дальнейшее продолжение пути способно уменьшить его стоимость. Кроме того, отрицательные циклы делают задачу кратчайшего пути некорректной. В таких случаях используют Беллмана–Форда или другие подходящие алгоритмы.

## 5.7 Как избегаются циклы в текущем пути?

Перед расширением состояния проверяется, что вершина-кандидат не содержится в текущем пути. Это исключает циклы и гарантирует конечность перебора для конечного графа.
