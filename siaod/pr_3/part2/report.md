## Архитектура проекта

### Представление графа

Выбран вариант: **список рёбер** (`std::vector<Edge>`) + число вершин `vertexCount_`. 

```cpp
struct Edge {
    int from = 0;
    int to = 0;
    int weight = 0;
};
```

Почему так:
- граф небольшой (6 вершин в варианте, произвольный ввод тоже обычно небольшой в лабораторной);
- удобно хранить ориентированные взвешенные рёбра;
- просто выводить рёбра и строить список исходящих соседей;
- для алгоритма дерева решений нам важна возможность получить исходящие рёбра вершины — это делается фильтрацией/перебором списка рёбер, что для малых графов достаточно.

Альтернативы: матрица смежности `O(V^2)` памяти, хороша для плотных графов и быстрого `hasEdge`; список смежности `vector<vector<pair<int,int>>>` — быстрее для обхода. Для данной задачи любой из этих вариантов корректен; выбран список рёбер как простой и наглядный.

### Проверки при добавлении ребра

`addEdge(from, to, weight)` возвращает `false`, если:
- вершина вне диапазона `1..vertexCount`;
- вес отрицательный;
- такое ребро `from->to` уже есть (дубликат запрещён).

## Алгоритм: кратчайший путь методом построения дерева решений

### Идея

Метод построения дерева решений (в данном контексте — поиск в пространстве состояний с отсечением, близкий к методу ветвей и границ) рассматривает процесс выбора пути как дерево:

- **корень** — начальная вершина, стоимость пути `g = 0`;
- **узел дерева** — состояние: текущая вершина, накопленная стоимость `g`, путь от источника;
- **ветвление** — из текущей вершины можно перейти по любому исходящему ребру в вершину, которая ещё не встречалась в текущем пути (чтобы не зацикливаться);
- **лист-цель** — достигнута целевая вершина;
- **лист-тупик** — нет допустимых исходящих переходов;
- **отсечение (граница)** — если текущая стоимость `g` уже не меньше стоимости лучшего найденного пути до цели, продолжать эту ветвь бессмысленно: добавление рёбер с неотрицательным весом не улучшит результат.

Такой перебор гарантирует нахождение оптимального пути, если веса рёбер неотрицательны (в предложенном графе все веса >= 0).

### Почему это работает

Пусть `best` — стоимость лучшего уже найденного полного пути от источника до цели. Рассмотрим частичный путь стоимости `g`. Любое его расширение имеет стоимость `g + w_extra`, где `w_extra >= 0` при неотрицательных весах. Если `g >= best`, то `g + w_extra >= best`, то есть полный путь через этот узел не может быть лучше уже найденного. Поэтому узел можно отсечь.

### Псевдокод

```text
ПОИСК_ДЕРЕВОМ_РЕШЕНИЙ(graph, source, target):
    best = НЕ_НАЙДЕНО, bestCost = +∞
    стек/очередь состояний = { (source, g=0, path=[source]) }

    пока есть состояния:
        (v, g, path) = извлечь состояние
        если best найдено и g >= bestCost: ОТСЕЧЬ; продолжить

        если v == target:
            если g < bestCost: best = path, bestCost = g
            продолжить

        candidates = исходящие рёбра из v, ведущие в вершины не из path
        если candidates пусто: ТУПИК; продолжить

        для каждого ребра (v -> u, w) в candidates:
            ng = g + w
            если best найдено и ng >= bestCost: ОТСЕЧЬ потомка
            иначе добавить (u, ng, path + [u]) в состояния

    вернуть best
```

В реализации используется DFS (стек). Потомки добавляются в стек в обратном порядке по номеру вершины-получателя, чтобы обход был детерминированным: меньший номер рассматривается раньше.

### Пошаговый разбор на предложенном графе (источник 1, цель 6)

Начальное состояние: `(1, g=0, path=[1])`, `best = +∞`.

1. Раскрываем `1`: соседи 2 (w=8), 3 (w=4). Создаём узлы для 3 и 2.
2. Идём в `3` (g=4): соседи 2,4,6. Генерируем 2(g=7),4(g=6),6(g=14).
3. Идём в `2` (g=7, путь 1-3-2): соседи 4,5. Генерируем 4(g=13),5(g=10).
4. Идём в `4` (g=13): `g >= ?` пока best нет. Соседи 5,6 дают 16,14.
5. Идём в `5` (g=16): сосед 6 даёт 20.
6. Идём в `6` (g=20): цель, `best = 20`, путь `1-3-2-4-5-6`.
7. Идём в `6` (g=14, путь 1-3-2-4-6): цель, `best = 14`.
8. Идём в `5` (g=10): сосед 6 даёт 14, но `14 >= best(14)` — **отсечение**.
9. Идём в `4` (g=6, путь 1-3-4): соседи 5,6 дают 9,7.
10. Идём в `5` (g=9): сосед 6 даёт 13 >= 14? нет, 13 < 14 — не отсекается. Переходим в 6: цель, `best = 13`, путь `1-3-4-5-6`.
11. Идём в `6` (g=7, путь 1-3-4-6): цель, `best = 7`, путь `1-3-4-6`.
12. Идём в `6` (g=14, путь 1-3-6): `14 >= 7` — **отсечение**.
13. Идём в `2` (g=8, путь 1-2): соседи 4,5 дают 14,11; 14>=7 отсечён, 11>=7 отсечён.

Итог: кратчайший путь `1 -> 3 -> 4 -> 6`, вес 7.

Этот разбор показывает, как граница `best` сокращает перебор: после нахождения пути стоимости 7 все ветви с `g >= 7` отсекаются.

## Сравнение с другими алгоритмами кратчайшего пути

Вариант 3 использует метод построения дерева решений. Ниже — сравнение с алгоритмами, встречающимися в теме практической работы.

| Алгоритм | Что находит | Веса | Сложность (типично) | Идея | Когда удобен |
|---|---|---|---|---|---|
| Дерево решений / ветви и границы | Кратчайший путь s→t | Неотрицательные (для отсечения) | Худший случай экспоненциальный, на малых графах быстро | Перебор путей с отсечением по текущей лучшей стоимости | Небольшие графы, наглядная демонстрация перебора и отсечений |
| Дейкстра | Кратчайшие пути от s до всех | Неотрицательные | `O((V+E) log V)` с кучей | Жадно выбирает вершину с минимальной текущей дистанцией | Быстрый поиск в графах без отрицательных весов |
| Беллман–Форд | Кратчайшие пути от s | Могут быть отрицательные (без отрицательных циклов) | `O(V*E)` | Релаксация всех рёбер V-1 раз | Есть отрицательные веса, обнаружение отрицательного цикла |
| Флойд–Уоршелл | Кратчайшие пути между всеми парами | Могут быть отрицательные (без отриц. циклов) | `O(V^3)` | Динамическое программирование по промежуточным вершинам | Нужны расстояния между всеми парами, граф небольшой |
| Алгоритм Йена | K кратчайших путей s→t | Неотрицательные (обычно) | Зависит от K и подалгоритма | Последовательно находит 1-й, 2-й, ..., K-й путь, удаляя рёбра/вершины | Нужны несколько альтернативных путей |

**Вывод по сравнению:** метод дерева решений прост для понимания и нагляден (видно дерево перебора и отсечения), но в худшем случае перебирает много путей. Для больших графов практичнее Дейкстра или Беллман–Форд. Для предложенного графа из 6 вершин дерево решений работает мгновенно.

## Код программы (ключевые фрагменты)

### Добавление ребра

```cpp
bool Graph::addEdge(int from, int to, int weight) {
    if (from < 1 || from > vertexCount_ || to < 1 || to > vertexCount_) return false;
    if (weight < 0) return false;
    for (const auto& e : edges_) {
        if (e.from == from && e.to == to) return false; // дубликат
    }
    edges_.push_back({from, to, weight});
    return true;
}
```

            else { /* создать узел дерева и положить в стек */ }
        }
    }
    return best;

## Ответы на контрольные вопросы

### 1. Что такое граф?

Граф — математическая структура `G = (V, E)`, где `V` — множество вершин, `E` — множество рёбер (пар вершин). Рёбра могут быть ориентированными/неориентированными, взвешенными/невзвешенными. В данной работе используется ориентированный взвешенный граф.

### 2. Какие способы представления графа в памяти существуют?

| Представление | Память | Проверка ребра | Перебор соседей | Когда удобно |
|---|---:|---:|---:|---|
| Матрица смежности | `O(V^2)` | `O(1)` | `O(V)` | Плотные графы, быстрые проверки |
| Список смежности | `O(V+E)` | `O(deg(v))` | `O(deg(v))` | Разреженные графы, обходы |
| Список рёбер | `O(E)` | `O(E)` | `O(E)` | Простая реализация, алгоритмы над рёбрами (Крускал) |
| Матрица инцидентности | `O(V*E)` | `O(E)` | `O(E)` | Редко, теоретические задачи |

В работе выбран список рёбер из-за простоты и малого размера графа.

### 3. Что такое дерево решений в контексте поиска кратчайшего пути?

Дерево решений — модель перебора вариантов: каждый узел соответствует частичному решению (текущему пути), ветви — возможным продолжениям, листья — полным путям или тупикам. Для кратчайшего пути узел хранит текущую вершину и стоимость `g`. Отсечение ветвей по границе `g >= best` превращает полный перебор в метод ветвей и границ.

### 4. Почему можно отсекать ветви при неотрицательных весах?

Если текущий частичный путь имеет стоимость `g >= best`, где `best` — стоимость уже найденного полного пути до цели, то любой расширенный путь будет иметь стоимость `g + w_extra >= g >= best`, поскольку `w_extra >= 0`. Значит, в этой ветви нет пути лучше текущего лучшего.

### 5. Чем этот метод отличается от Дейкстры?

Дейкстра поддерживает минимальные известные расстояния до всех вершин и жадно раскрывает вершину с наименьшей дистанцией, гарантируя оптимальность за полиномиальное время при неотрицательных весах. Дерево решений перебирает пути (состояния) и может посещать одну и ту же вершину в разных ветвях с разными путями; оно наглядно, но в худшем случае экспоненциально. Дейкстра эффективнее на больших графах.

### 6. Что будет, если в графе есть отрицательные веса?

Отсечение `g >= best` остаётся корректным только если нельзя получить улучшение за счёт отрицательного продолжения — но при отрицательных рёбрах это не так. Кроме того, отрицательные циклы делают кратчайший путь неопределённым. Для отрицательных весов нужны Беллман–Форд или другие алгоритмы с соответствующими ограничениями.

### 7. Как проверяется отсутствие циклов в текущем пути?

Перед добавлением потомка проверяется, что вершина-получатель не входит в текущий путь `path`. Это исключает циклы и гарантирует конечность дерева решений в конечном графе.
