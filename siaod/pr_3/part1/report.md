## Архитектура проекта

### Структуры данных

```cpp
enum class Color : unsigned char { Red, Black };

struct Node {
    char key = '\0';
    Color color = Color::Red;
    Node* left = nullptr;
    Node* right = nullptr;
    Node* parent = nullptr;
};
```

Класс `RBTree` хранит:
- `root_` — корень дерева;
- `nil_` — общий sentinel-узел (чёрный лист NIL), на который указывают все пустые дети/родитель корня;
- `size_` — количество реальных узлов.

Использование sentinel `nil_` упрощает код: не нужно проверять `nullptr` в каждом повороте и при балансировке, все листья представлены одним чёрным узлом.

### Почему ключ — `char`

По варианту тип значения узла — символ. В программе ключ хранится как `char`. Сравнение при вставке и поиске выполняется по значению `char` (его коду). Для операций «сумма значений листьев» и «среднее арифметическое всех узлов» символы интерпретируются как числовые коды `unsigned char`, чтобы результат был однозначным и не зависел от знаковости `char` на платформе. Это явно выводится в меню.

## Математическая модель и алгоритмы

### 1. Двоичное дерево поиска (BST)

BST-свойство: для любого узла `x` все ключи в левом поддереве меньше `x.key`, все ключи в правом поддереве больше `x.key`. В данной реализации дубликаты не вставляются.

Симметричный обход BST всегда выдаёт ключи в отсортированном порядке — это используется в тестах как проверка корректности.

### 2. Красно-чёрное дерево

Красно-чёрное дерево — это BST с дополнительными свойствами, которые гарантируют, что высота дерева остаётся `O(log n)`.

**Инварианты КЧ-дерева:**
1. Каждый узел либо красный, либо чёрный.
2. Корень чёрный.
3. Все листья `nil` чёрные.
4. У красного узла оба потомка чёрные (нет двух красных подряд по пути).
5. Для любого узла все простые пути от него до листьев `nil` содержат одинаковое число чёрных узлов (чёрная высота).

Из этих свойств следует, что высота дерева с `n` внутренними узлами не превосходит `2 * log2(n + 1)`.

### 3. Повороты

Повороты — локальные операции, сохраняющие BST-свойство и используемые при балансировке.

**Левый поворот вокруг `x`** (правый ребёнок `y` поднимается):
```text
    x                y
   / \              / \
  a   y    ->      x   c
     / \          / \
    b   c        a   b
```

**Правый поворот вокруг `y`** — зеркальный.

Сложность поворота: `O(1)`.

### 4. Вставка в КЧ-дерево

Алгоритм вставки состоит из двух фаз:

1. **Обычная BST-вставка.** Новый узел `z` вставляется как в обычном BST, красится в красный цвет, его дети — `nil`. Красный цвет выбран потому, что он не нарушает свойство чёрной высоты (свойство 5), но может нарушить свойство 4, если родитель тоже красный.
2. **Исправление нарушений (`insertFixup`).** Пока родитель `z` красный, выполняется один из трёх случаев (для случая, когда отец — левый ребёнок деда; справа — зеркально):

| Случай | Условие | Действие | Результат |
|---|---|---|---|
| 1 | Дядя красный | Отец и дядя -> чёрные, дед -> красный; `z = дед` | Возможно нарушение выше, цикл продолжается |
| 2 | Дядя чёрный, `z` — правый ребёнок | `z = отец`, левый поворот вокруг `z` | Переход к случаю 3 |
| 3 | Дядя чёрный, `z` — левый ребёнок | Отец -> чёрный, дед -> красный, правый поворот вокруг деда | Нарушение устранено, цикл завершается |

После цикла корень принудительно красится в чёрный.

**Сложность вставки:** `O(log n)` — спуск по дереву `O(log n)` + не более двух поворотов и `O(log n)` перекрашиваний.

### 5. Обходы дерева

| Обход | Порядок посещения | Реализация | Сложность |
|---|---|---|---|
| Прямой (preorder) | Узел -> Левое -> Правое | Рекурсия | `O(n)` |
| Симметричный (inorder) | Левое -> Узел -> Правое | Рекурсия | `O(n)` |

Для BST симметричный обход возвращает ключи по возрастанию.

### 6. Сумма значений листьев

Лист — узел, у которого оба потомка являются `nil`.

Алгоритм: рекурсивный обход дерева; если узел — лист, добавить `unsigned char(key)` к сумме.

```text
SUM_LEAVES(node):
    если node = nil: вернуть 0
    если node.left = nil и node.right = nil:
        вернуть code(node.key)
    вернуть SUM_LEAVES(node.left) + SUM_LEAVES(node.right)
```

Сложность: `O(n)` по времени, `O(h)` по памяти стека вызовов.

### 7. Среднее арифметическое всех узлов

Алгоритм: рекурсивно обойти все узлы, накопить сумму кодов и количество узлов.

```text
AVERAGE:
    если дерево пустое: вернуть "не определено"
    (sum, count) = WALK(root)
    вернуть sum / count
```

Сложность: `O(n)`.

## Код программы (ключевые фрагменты)

### Вставка и балансировка

```cpp
bool RBTree::insert(char key) {
    Node* parent = nil_;
    Node* cur = root_;
    while (cur != nil_) {
        parent = cur;
        if (key == cur->key) return false; // дубликат
        cur = (key < cur->key) ? cur->left : cur->right;
    }

    Node* z = new Node{};
    z->key = key;
    z->color = Color::Red;
    z->left = z->right = nil_;
    z->parent = parent;

    if (parent == nil_) root_ = z;
    else if (key < parent->key) parent->left = z;
    else parent->right = z;

    ++size_;
    insertFixup(z);
    return true;
}
```

`insertFixup` реализует три случая (и их зеркальные версии) с перекрашиванием и поворотами, после чего корень окрашивается в чёрный.

### Проверка инвариантов

Метод `validate()` проверяет: `nil` чёрный, корень чёрный, нет красного узла с красным потомком, связи `parent` корректны, BST-свойство соблюдено, чёрная высота одинакова по всем путям. Это используется в автотестах после каждой вставки в случайных сценариях.

## Ответы на контрольные вопросы

### 1. Что такое двоичное дерево поиска?

Двоичное дерево поиска (BST) — двоичное дерево, в котором для каждого узла все ключи левого поддерева меньше ключа узла, а все ключи правого поддерева больше. Это позволяет выполнять поиск, вставку и удаление в среднем за `O(log n)`, но в худшем случае (вырожденное дерево) — за `O(n)`.

### 2. Почему обычное BST может работать плохо?

Если ключи приходят в отсортированном или почти отсортированном порядке, BST вырождается в список: каждый новый узел уходит в одну сторону. Высота становится `n`, а операции поиска/вставки — `O(n)`. Балансирующиеся деревья (AVL, красно-чёрное) решают эту проблему.

### 3. Что такое красно-чёрное дерево и какие у него свойства?

Красно-чёрное дерево — самобалансирующееся BST, где каждый узел окрашен в красный или чёрный цвет и соблюдаются 5 инвариантов: узел красный/чёрный; корень чёрный; листья NIL чёрные; у красного узла дети чёрные; все пути от узла до NIL-листьев имеют одинаковую чёрную высоту. Эти свойства гарантируют высоту не более `2*log2(n+1)`.

### 4. Зачем нужен sentinel NIL?

Sentinel `nil` — общий чёрный узел, заменяющий все `nullptr`-листья. Он упрощает код поворотов и балансировки: не нужно отдельно обрабатывать отсутствие ребёнка, можно единообразно обращаться к `node->left/right/parent`. В реализации `nil_->parent/left/right` указывают на `nil_`.

### 5. Как работает балансировка при вставке?

Новый узел вставляется как красный. Если его родитель чёрный — всё нормально. Если родитель красный — нарушено свойство 4, и запускается `insertFixup`: в случае красного дяди выполняется перекрашивание и подъём вверх; в случаях чёрного дяди выполняются повороты и перекрашивание, после чего нарушение устраняется. Корень в конце всегда делается чёрным.

### 6. Чем КЧ-дерево отличается от AVL-дерева?

| Критерий | AVL | Красно-чёрное |
|---|---|---|
| Критерий баланса | Разница высот поддеревьев <= 1 | Чёрная высота путей одинакова, нет двух красных подряд |
| Высота | Строже сбалансировано, ~1.44*log2(n) | До 2*log2(n+1) |
| Поиск | Обычно чуть быстрее (дерево ниже) | Чуть медленнее в худшем случае |
| Вставка/удаление | Больше поворотов в среднем | Меньше поворотов, быстрее при частых изменениях |
| Применение | Частые поиски | Частые вставки/удаления (map/set в стандартных библиотеках) |

### 7. Какие обходы дерева бывают?

- **Прямой (preorder, NLR):** узел, левое поддерево, правое поддерево. Удобен для копирования/сериализации структуры.
- **Симметричный (inorder, LNR):** левое, узел, правое. Для BST даёт отсортированный порядок.
- **Обратный (postorder, LRN):** левое, правое, узел. Удобен для удаления/освобождения дерева.
- **В ширину (BFS, level-order):** по уровням, слева направо, обычно через очередь.

В варианте 3 реализованы preorder и inorder.

### 8. Как считаются сумма листьев и среднее?

Лист — узел без реальных детей (оба ребёнка — `nil`). Сумма листьев — сумма числовых кодов `unsigned char` ключей-листьев. Среднее арифметическое всех узлов — сумма кодов всех узлов / количество узлов. Для пустого дерева сумма листьев равна 0, среднее не определено.
