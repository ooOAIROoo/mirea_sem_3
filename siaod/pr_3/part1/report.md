# 1 Теоретические сведения

## 1.1 Двоичное дерево поиска

Двоичное дерево поиска (Binary Search Tree, BST) — двоичное дерево, для каждого узла `x` которого выполняется свойство: все ключи левого поддерева меньше `x.key`, все ключи правого поддерева больше `x.key`.

При сбалансированной форме высота BST равна `O(log n)`, и операции поиска, вставки и удаления выполняются за `O(log n)`. Если ключи поступают в отсортированном или неудачном порядке, дерево может выродиться в список, и высота станет `O(n)`.

## 1.2 Красно-чёрное дерево

Красно-чёрное дерево (Red-Black Tree, RBT) — самобалансирующееся BST, в котором каждый узел имеет цвет (красный или чёрный), а баланс поддерживается набором инвариантов.

Table: Таблица 1 — Инварианты красно-чёрного дерева

| № | Инвариант | Смысл |
|---:|---|---|
| 1 | Каждый узел красный или чёрный | Хранится цвет узла |
| 2 | Корень чёрный | Фиксирует верхнюю границу |
| 3 | Все листья NIL чёрные | Пустые дети считаются чёрными узлами |
| 4 | У красного узла оба потомка чёрные | Запрещены два красных узла подряд |
| 5 | Все пути от узла до NIL-листьев содержат одинаковое число чёрных узлов | Одинаковая чёрная высота |

Из этих свойств следует, что высота красно-чёрного дерева с `n` внутренними узлами не превышает `2·log2(n + 1)`, поэтому операции поиска и вставки имеют сложность `O(log n)`.

## 1.3 Повороты и балансировка при вставке

Повороты — локальные преобразования, сохраняющие BST-свойство. Левый поворот поднимает правого потомка, правый поворот — левого. Каждый поворот выполняется за `O(1)`.

Вставка состоит из двух фаз. Сначала выполняется обычная вставка BST: новый узел окрашивается в красный цвет, его дети указывают на sentinel `nil`. Затем запускается процедура `insertFixup`: пока родитель нового узла красный, нарушение свойства 4 устраняется перекрашиванием и/или поворотами.

Table: Таблица 2 — Случаи балансировки при вставке (отец — левый ребёнок деда)

| Случай | Условие | Действие | Результат |
|---|---|---|---|
| 1 | Дядя красный | Отец и дядя становятся чёрными, дед — красным; текущий узел = дед | Нарушение может подняться выше |
| 2 | Дядя чёрный, текущий узел — правый ребёнок | Левый поворот вокруг отца | Переход к случаю 3 |
| 3 | Дядя чёрный, текущий узел — левый ребёнок | Отец становится чёрным, дед — красным, правый поворот вокруг деда | Нарушение устранено |

Для случая, когда отец является правым ребёнком деда, выполняются зеркальные действия.

## 1.4 Обходы дерева

Table: Таблица 3 — Обходы двоичного дерева

| Обход | Порядок | Свойство | Сложность |
|---|---|---|---|
| Прямой (preorder, NLR) | Узел — левое — правое | Удобен для копирования структуры | `O(n)` |
| Симметричный (inorder, LNR) | Левое — узел — правое | Для BST выдаёт ключи по возрастанию | `O(n)` |
| Обратный (postorder, LRN) | Левое — правое — узел | Удобен для освобождения дерева | `O(n)` |
| В ширину (BFS, level-order) | По уровням слева направо | Использует очередь | `O(n)` |

# 3 Реализация

## 3.1 Представление данных

Узел дерева хранит ключ, цвет и указатели на родителя и потомков. Класс `RBTree` использует общий sentinel-узел `nil_` — чёрный фиктивный лист, на который указывают все пустые ссылки. Это избавляет от многочисленных проверок на `nullptr` в поворотах и балансировке.

::: {custom-style="ListingCaption"}
Листинг 4 — Структуры узла и класс дерева (фрагмент `include/rbtree.hpp`)
:::

```cpp
enum class Color : unsigned char { Red, Black };

struct Node {
    char key = '\0';
    Color color = Color::Red;
    Node* left = nullptr;
    Node* right = nullptr;
    Node* parent = nullptr;
};

class RBTree {
public:
    bool insert(char key);
    std::vector<char> preorder() const;
    std::vector<char> inorder() const;
    long long sumLeaves() const;
    std::vector<char> leaves() const;
    std::optional<double> averageAll() const;
    bool validate(std::ostream* err = nullptr) const;
    // ...
private:
    Node* root_ = nullptr;
    Node* nil_ = nullptr;
    std::size_t size_ = 0;
};
```

Ключ имеет тип `char` в соответствии с вариантом. Для операций «сумма значений листьев» и «среднее арифметическое всех узлов» символы интерпретируются как числовые коды `unsigned char`. Такое преобразование даёт однозначный числовой результат и не зависит от знаковости `char` на конкретной платформе.

## 3.2 Вставка и балансировка

Вставка выполняется в два этапа: обычная BST-вставка нового красного узла и восстановление свойств КЧ-дерева процедурой `insertFixup`.

::: {custom-style="ListingCaption"}
Листинг 5 — Вставка узла (фрагмент `src/rbtree.cpp`)
:::

```cpp
bool RBTree::insert(char key) {
    Node* parent = nil_;
    Node* cur = root_;
    while (cur != nil_) {
        parent = cur;
        if (key == cur->key) return false; // дубликат
        cur = (key < cur->key) ? cur->left : cur->right;
    }

    Node* z = new Node{};
    z->key = key;
    z->color = Color::Red;
    z->left = z->right = nil_;
    z->parent = parent;

    if (parent == nil_) root_ = z;
    else if (key < parent->key) parent->left = z;
    else parent->right = z;

    ++size_;
    insertFixup(z);
    return true;
}
```

Процедура `insertFixup` обрабатывает три случая (и их зеркальные версии), описанные в таблице 2. После завершения цикла корень принудительно окрашивается в чёрный цвет, что восстанавливает свойство 2.

Сложность вставки: `O(log n)` по времени, `O(1)` дополнительной памяти (без учёта рекурсии — вставка итеративная, fixup также итеративный).

## 3.3 Обходы

Прямой обход посещает узлы в порядке «узел — левое поддерево — правое поддерево». Симметричный обход посещает узлы в порядке «левое поддерево — узел — правое поддерево». Для BST симметричный обход возвращает ключи в отсортированном порядке, что используется в тестах как проверка корректности.

::: {custom-style="ListingCaption"}
Листинг 6 — Рекурсивные обходы (фрагмент `src/rbtree.cpp`)
:::

```cpp
void RBTree::preorderRec(Node* node, std::vector<char>& out) const {
    if (node == nil_) return;
    out.push_back(node->key);
    preorderRec(node->left, out);
    preorderRec(node->right, out);
}

void RBTree::inorderRec(Node* node, std::vector<char>& out) const {
    if (node == nil_) return;
    inorderRec(node->left, out);
    out.push_back(node->key);
    inorderRec(node->right, out);
}
```

## 3.4 Сумма листьев и среднее арифметическое

Лист — узел, у которого оба потомка равны `nil_`. Сумма листьев вычисляется как сумма кодов `unsigned char` всех листовых узлов. Среднее арифметическое вычисляется как сумма кодов всех узлов, делённая на количество узлов; для пустого дерева среднее не определено.

::: {custom-style="ListingCaption"}
Листинг 7 — Вычисление суммы листьев (фрагмент `src/rbtree.cpp`)
:::

```cpp
void RBTree::sumLeavesRec(Node* node, long long& sum, std::size_t& count) const {
    if (node == nil_) return;
    const bool isLeaf = (node->left == nil_ && node->right == nil_);
    if (isLeaf) {
        sum += static_cast<unsigned char>(node->key);
        ++count;
        return;
    }
    sumLeavesRec(node->left, sum, count);
    sumLeavesRec(node->right, sum, count);
}
```

Обе операции обходят дерево целиком, поэтому имеют сложность `O(n)` по времени и `O(h)` по памяти стека, где `h` — высота дерева.

## 3.5 Проверка инвариантов

Для контроля корректности реализован метод `validate()`. Он проверяет: `nil` чёрный; корень чёрный; у красного узла нет красных потомков; связи `parent` корректны; BST-свойство соблюдено; чёрная высота всех путей от узла до `nil` одинакова. Этот метод используется в автоматических тестах после каждой вставки.

# 5 Ответы на контрольные вопросы

## 5.1 Что такое двоичное дерево поиска?

Двоичное дерево поиска (BST) — двоичное дерево, в котором для каждого узла все ключи левого поддерева меньше ключа узла, а все ключи правого поддерева больше. Это свойство позволяет выполнять поиск, вставку и удаление в среднем за `O(log n)`, но в худшем случае — за `O(n)` при вырождении дерева.

## 5.2 Почему обычное BST может работать плохо?

Если ключи поступают в отсортированном или почти отсортированном порядке, узлы добавляются преимущественно в одну сторону. Дерево вырождается в список, высота становится `n`, а операции поиска и вставки — `O(n)`. Самобалансирующиеся деревья (AVL, красно-чёрное) предотвращают это, поддерживая ограничение на высоту.

## 5.3 Что такое красно-чёрное дерево и какие у него свойства?

Красно-чёрное дерево — самобалансирующееся BST, где каждый узел окрашен в красный или чёрный цвет и соблюдаются пять инвариантов: корень чёрный; NIL-листья чёрные; у красного узла дети чёрные; все пути от узла до NIL имеют одинаковую чёрную высоту. Эти свойства гарантируют высоту не более `2·log2(n+1)`.

## 5.4 Зачем нужен sentinel NIL?

Sentinel `nil` — общий чёрный узел, заменяющий пустые ссылки. Он упрощает реализацию поворотов и балансировки: код одинаково работает с обычными узлами и листьями, не требуя специальных проверок на `nullptr`.

## 5.5 Как работает балансировка при вставке?

Новый узел вставляется как красный. Если его родитель чёрный, инварианты не нарушены. Если родитель красный, нарушается свойство 4. Процедура `insertFixup` устраняет нарушение: при красном дяде выполняется перекрашивание и подъём к деду; при чёрном дяде выполняются повороты и перекрашивание, после чего нарушение устраняется. В конце корень окрашивается в чёрный.

## 5.6 Чем КЧ-дерево отличается от AVL-дерева?

Table: Таблица 8 — Сравнение AVL и красно-чёрного дерева

| Критерий | AVL-дерево | Красно-чёрное дерево |
|---|---|---|
| Критерий баланса | Разница высот поддеревьев <= 1 | Ограничения на цвета и чёрную высоту |
| Высота | Строже сбалансировано, ~`1.44·log2(n)` | До `2·log2(n+1)` |
| Поиск | Обычно немного быстрее | Немного медленнее в худшем случае |
| Вставка/удаление | В среднем больше поворотов | Обычно меньше поворотов |
| Типичное применение | Много поисков, мало изменений | Много вставок/удалений (например, `std::map`) |

## 5.7 Какие обходы дерева бывают?

Прямой (preorder, NLR) — узел, левое, правое; симметричный (inorder, LNR) — левое, узел, правое; обратный (postorder, LRN) — левое, правое, узел; обход в ширину (BFS) — по уровням. В варианте 3 реализованы preorder и inorder.

## 5.8 Как считаются сумма листьев и среднее арифметическое?

Лист — узел без реальных потомков (оба потомка — `nil`). Сумма листьев — сумма кодов `unsigned char` ключей-листьев. Среднее арифметическое — сумма кодов всех узлов, делённая на количество узлов. Для пустого дерева сумма листьев равна 0, среднее не определено.

В ходе практической работы реализовано красно-чёрное дерево для ключей типа `char` в соответствии с вариантом 3. Программа поддерживает вставку с балансировкой, прямой и симметричный обходы, вычисление суммы значений листьев и среднего арифметического всех узлов. Корректность реализации подтверждена автоматическими тестами, включая 200 случайных прогонов с проверкой инвариантов после каждой вставки, а также ручным тестированием на наборе из 10 элементов. Цель работы достигнута, поставленные задачи выполнены.
