# Практическая работа № 6.1: хеш-таблица, вариант 3

Консольное приложение хранит сведения о студентах: **номер зачётной книжки** (уникальный ключ), номер группы и ФИО. Для поиска используется хеш-таблица с открытой адресацией и **двойным хешированием**. Поддерживаются вставка, поиск, удаление и вывод. При запуске автоматически добавляются шесть демонстрационных студентов.

Программа работает в памяти: после выхода изменения не сохраняются в файл. При следующем обычном запуске снова создаётся исходный демонстрационный набор.

## Состав проекта

## Сборка и запуск

Потребуются CMake **3.16 или новее** и компилятор с поддержкой C++17. Сторонние библиотеки и Python для программы и тестов не нужны. Все приведённые команды выполняются из каталога `siaod/pr_2`.

### Linux

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
./build/pr_2_app
```

Для пустой таблицы или справки:

```bash
./build/pr_2_app --empty
./build/pr_2_app --help
```

### Windows

Установите CMake и, например, Visual Studio 2019/2022 с компонентом «Разработка классических приложений на C++». В PowerShell:

```powershell
cmake -S . -B build
cmake --build build --config Release
.\build\Release\pr_2_app.exe
```

Параметры аналогичны Linux: `.\build\Release\pr_2_app.exe --empty` и `.\build\Release\pr_2_app.exe --help`. Для одноконфигурационного генератора, например MinGW Makefiles, exe обычно находится непосредственно в `build`: `.\build\pr_2_app.exe`. Если меняете генератор или компилятор, используйте новый каталог сборки.

Исходники сохранены в UTF-8; CMake передаёт MSVC ключ `/utf-8`. В Windows приложение включает UTF-8 для вывода, а ввод из настоящей консоли читает через `ReadConsoleW` и преобразует из UTF-16 в UTF-8. При перенаправлении стандартного ввода ожидаются байты UTF-8. Для кириллицы рекомендуется современный Windows Terminal или консоль Windows с поддержкой UTF-8; в Linux терминал также должен использовать UTF-8.

### Автоматические тесты

После сборки запустите из `siaod/pr_2`:

```text
cd build
ctest -C Release --output-on-failure
cd ..
```

`hash_table_tests` проверяет хеши, полный обход ячеек, ввод, дубликаты, коллизии, удаление и повторное использование ячеек, рост и рехеширование. Также выполняются 12 000 воспроизводимых случайных операций со сравнением с эталонным словарём. `cli_workflow` подаёт команды настоящему приложению и проверяет, в частности, поиск после удаления столкнувшегося ключа, отказ от дубликата, оба вида рехеширования, пустую таблицу и завершение ввода. Тесты не требуют существующих файлов с данными.

## Интерфейс и ввод

Без параметров программа загружает набор из шести записей с ключами `1001`, `1013`, `1098`, `2024001`, `2024002`, `2024003`. Все поля набора заданы в функции `demoStudents()`; данные не скачиваются и не читаются из внешних файлов. Параметр `--empty` запускает программу без этих записей.

В меню доступны:

1. **Добавить студента** — последовательно ввести номер зачётной книжки, группу и ФИО. Если номер уже существует, запись не изменяется.
2. **Найти студента** — ввести ключ; программа покажет запись, индекс ячейки и индекс данных либо сообщит, что записи нет.
3. **Удалить студента** — ввести ключ. Отсутствие ключа не считается ошибкой.
4. **Показать массив записей** — вывести все существующие записи с индексами в массиве данных.
5. **Показать хеш-таблицу** — вывести каждую ячейку, её состояние, ключ, `h1`, `h2` и индекс записи.
0. **Выход**.

Пункты можно выбирать в любом порядке. Пустые поля запрашиваются повторно; конец ввода завершает программу. При вводе крайние ASCII-пробелы и другие пробельные символы по краям убираются, пробелы внутри группы и ФИО сохраняются. Многострочные поля не поддерживаются.

Номер зачётной книжки хранится как строка: в задании его числовой формат не ограничен. Поэтому доступны номера с буквами и ведущими нулями; `0001` и `1` — разные ключи. Сравнение учитывает регистр и выполняется по байтам, без приведения регистра или нормализации Unicode. Предполагается ввод текста в UTF-8; отдельных ограничений на длину номера и состав ФИО программа не задаёт.

## Как устроены данные

`StudentHashTable` содержит два разных динамических массива:

- `records_` — массив `std::optional<Student>` с полезными данными. Пустая позиция возникает после удаления; её индекс запоминается в `freeRecordIndices_` и может быть повторно использован при вставке.
- `table_` — массив ячеек хеш-таблицы. Каждая ячейка имеет состояние **пусто**, **занято** или **удалено**. Занятая ячейка содержит ключ и индекс записи в `records_`.

Номер занятой ячейки является вычисленным адресом ключа с учётом проб — в этом смысле таблица хранит соответствие «ключ → хеш-адрес». Индекс записи позволяет перейти к полным сведениям без просмотра массива студентов. В выводе `h1` — первоначальный адрес, `h2` — шаг; они рассчитываются заново по ключу и текущему размеру таблицы. Все индексы начинаются с нуля. При рехешировании индексы записей в массиве данных сохраняются, а их адреса в хеш-таблице могут измениться.

Результат метода `find` содержит указатель на найденного студента. Его следует использовать только до следующей изменяющей операции над таблицей: увеличение массива или удаление могут сделать указатель недействительным.

## Хеш-функции и пробы

Пусть `m` — текущий размер хеш-таблицы. Он всегда прост: сначала `11`, затем `23`, `47` и т. д. Для каждого байта `byte` строки ключа вычисляются два полинома в типе `uint64_t`:

```text
P_b = 0
P_b = (P_b * b + byte) mod 2^64    для каждого байта ключа
h1 = P_31 mod m
h2 = 1 + P_37 mod (m - 1)
адрес пробы i = (h1 + i * h2) mod m,  i = 0, 1, ..., m - 1
```

Переполнение беззнакового `uint64_t` в C++ определено как вычисление по модулю `2^64`. Это обычное некриптографическое хеширование; ключи всегда дополнительно сравниваются целиком. Из простоты `m` и условия `1 ≤ h2 < m` следует взаимная простота шага и размера, поэтому последовательность может посетить **каждую** ячейку ровно один раз. Число проб в любой операции ограничено `m`.

Например, при `m = 11` ключи `1001` и `1098` имеют `h1 = 6`, `h2 = 5`. `1001` занимает ячейку 6, а столкнувшийся с ним `1098` попадает в `(6 + 5) mod 11 = 0`. У `1013` тоже `h1 = 6`, но шаг `h2 = 4`; при начальном заполнении он занимает ячейку 10.

## Как работают операции

- **Поиск** вычисляет `h1` и `h2`, проверяет ячейки в порядке проб и сравнивает ключи. Он заканчивается при совпадении, при встрече ячейки, которая никогда не была занята, или после `m` проб. Через метку удаления поиск продолжается.
- **Вставка** сначала проверяет все необходимые пробы на наличие дубликата. Затем при необходимости перестраивает таблицу и ищет место, запоминая первую метку удаления. Новые данные помещаются в свободную или добавленную позицию массива записей; ключ и индекс этой позиции — в выбранную ячейку. Благодаря проверке дубликата запись не может повторно появиться за меткой удаления.
- **Удаление** находит ключ тем же путём, освобождает запись в массиве данных и оставляет в хеш-таблице метку `удалено`, а не обычную пустую ячейку. Иначе поиск других ключей, прошедших через эту позицию, мог бы преждевременно остановиться.
- **Вывод** по выбору показывает сами записи либо все состояния хеш-таблицы. Метки удаления видны во втором представлении.

## Расширение и рехеширование

Пусть `n` — число существующих записей, `t` — число меток удаления, `m` — размер таблицы. Перед вставкой **нового** ключа программа применяет порог `floor(0,7 × m)`:

1. Если `n + 1` превысит порог, выбирается наименьшее простое число не меньше `2 × m`. Создаётся новая таблица, и все существующие ключи размещаются заново с пересчитанными `h1` и `h2`. Например, `11 → 23`.
2. Иначе, если `n + t + 1` превысит порог, таблица перестраивается в том же размере: живые ключи размещаются заново, а метки удаления исчезают. Это делается до выбора места, даже если новая запись потенциально могла бы занять одну из меток.
3. В остальных случаях перестройка не нужна. Поиск, удаление и попытка вставки дубликата сами по себе её не вызывают.

При `m = 11` порог равен 7: первые семь записей помещаются без расширения, а вставка восьмой существующей одновременно записи вызывает рост до 23. Таблица автоматически не уменьшается.

## Ручная демонстрация

Для проверки коллизии и удаления запустите приложение без параметров:

1. Выберите `5`: посмотрите ячейки `6`, `10` и `0`. У ключей `1001`, `1013` и `1098` одинаковый первоначальный адрес `h1 = 6`.
2. Выберите `2`, введите `1098` и найдите студента. Затем через `3` удалите `1001`.
3. Снова выполните поиск `1098`: он должен пройти через метку удаления. Через `5` можно увидеть метку в ячейке 6.
4. Попробуйте добавить `1098` с любыми непустыми группой и ФИО: программа откажет в создании дубликата, несмотря на метку перед этим ключом.
5. Добавьте обратно `1001`, затем новых студентов с ключами `7777` и `8888`. После последней вставки появится сообщение о расширении `11 → 23`. Через `5` можно увидеть новое расположение ключей.

Для проверки очистки меток без роста запустите `--empty`, добавьте семь разных ключей `1`–`7` с непустыми группой и ФИО, удалите `1`, `2`, `3` и добавьте `8`. Программа сообщит о рехешировании без расширения: до вставки было четыре записи и три метки, а размер остался 11.

## Сложность

При хорошем распределении и ограниченной нагрузке число проб для поиска, вставки и удаления в среднем постоянно; вычисление хеша и сравнение строк дополнительно зависят от длины ключа. В худшем случае операция делает до `m` проб. Рехеширование проходит старую таблицу и заново вставляет все ключи; его стоимость также зависит от числа проб и длины ключей. Память занимает таблица и массив данных с местом для повторного использования удалённых записей; массив данных не сжимается автоматически.
