## Программа части 6.2 (part_2)

Исполняемый файл — `text_search_app`. Без параметров запускается меню:

1. **Самое длинное слово, первая и последняя буквы которого одинаковы.** Вводится предложение; слово — непрерывная последовательность букв (латиница или кириллица, включая `Ё/ё`), знаки препинания и пробелы — разделители. Концы слова сравниваются без учёта регистра, длина измеряется буквами (в UTF-8 буква кириллицы занимает два байта), однобуквенные слова подходят, при равной длине остаётся первое слово. Выводятся слово, число букв и позиция; если подходящих слов нет — сообщение об этом.
2. **КМП: индекс последнего вхождения образца в текст.** Вводятся текст (одна строка, длина не ограничена) и образец. Программа выводит индексы первого и последнего вхождений и число сравнений каждого поиска; если вхождений нет — сообщение и число сравнений. Индексация с нуля; для ASCII байтовый индекс совпадает с номером символа, для текстов с кириллицей печатаются оба значения (символ и байт).
3. **Демонстрация КМП** — префикс-функция образца и все (в том числе перекрывающиеся) вхождения плюс сравнение числа сравнений КМП и наивного алгоритма.
0. Выход.

Параметры запуска: `--demo` — прогон готовых примеров из отчёта с числами сравнений; `--bench` — таблицы практической сложности наивного поиска и КМП; `--help` — справка. Ввод читается построчно, пустые поля запрашиваются повторно, конец потока ввода корректно завершает программу.

Состав `part_2`: `include/text_search.hpp` — интерфейс библиотеки, `src/text_search.cpp` — префикс-функция, КМП и наивный поиск, `src/main.cpp` — меню и бенчмарк, `tests/` — автотесты и сценарии, `report.md` — отчёт.

## Отличия алгоритмов поиска образца в тексте

Задание и вопросы для самоподготовки упоминают пять алгоритмов. Кратко — идея каждого и чем они отличаются; псевдокод на русском.

| Алгоритм | Предобработка | Время (худшее) | Время (среднее) | Память | Ключевое отличие |
|---|---|---|---|---|---|
| Наивный | нет | `O(n·m)` | `O(n)` | `O(1)` | Сравнивает с каждой позиции заново |
| КМП | `O(m)` — префикс-функция | `O(n + m)` | `O(n + m)` | `O(m)` | Не возвращается по тексту: использует границы совпавшей части |
| Бойер — Мур (Хорспул) | `O(m + σ)` — таблица сдвигов | `O(n·m)` | подлинейное, ≈ `O(n/m)` | `O(σ)` | Сравнивает с конца образца и сдвигает большими прыжками |
| Рабин — Карп | `O(m)` — хеш образца | `O(n·m)` | `O(n + m)` | `O(1)` | Фильтрует позиции хешем, сравнивает только при совпадении хешей |
| Ахо — Корасик | `O(m)` — бор + суффиксные ссылки | `O(n + m + z)` | `O(n + m + z)` | `O(m·σ)` | Ищет **множество** образцов за один проход текста |

Здесь `n` — длина текста, `m` — суммарная длина образцов, `σ` — размер алфавита, `z` — число найденных вхождений.

### Наивный (последовательный) поиск

Прикладывает образец к каждой позиции текста и сравнивает посимвольно; при несовпадении сдвигается ровно на один символ. Простейший и без предобработки, но не использует уже найденную информацию — на периодических текстах вырождается до `n·m` сравнений.

```text
НАИВНЫЙ_ПОИСК(текст T длины n, образец P длины m):
    для start от 0 до n - m:
        k ← 0
        пока k < m и T[start + k] = P[k]:
            k ← k + 1
        если k = m:
            вернуть start          # вхождение найдено
    вернуть НЕ_НАЙДЕНО
```

### Кнут — Моррис — Пратт

Перед поиском строит префикс-функцию образца. Когда совпало `j` символов и произошло несовпадение, КМП заменяет совпавшую часть на её наибольшую границу (`π[j-1]`) и продолжает с того же символа текста: текстовый указатель никогда не движется назад, каждый символ текста участвует в `O(1)` амортизированных сравнениях. Отсюда гарантированные `O(n + m)` и надёжность на любых данных, включая периодические. Найдя вхождение и продолжая с `π[m-1]`, за один проход получают все перекрывающиеся вхождения — так в работе ищется последнее.

```text
КМП_ПОИСК(T, P):
    π ← ПРЕФИКС_ФУНКЦИЯ(P)
    j ← 0                       # сколько символов образца уже совпало
    для i от 0 до n - 1:
        пока j > 0 и T[i] ≠ P[j]:
            j ← π[j - 1]        # совпавшая часть сжимается до границы
        если T[i] = P[j]:
            j ← j + 1
        если j = m:
            вхождение на i - m + 1
            j ← π[j - 1]        # продолжаем: следующие вхождения могут перекрываться
```

### Бойер — Мур (эвристика Хорспула)

Единственный из перечисленных сравнивает образец **справа налево**. Несовпадение обнаруживается обычно уже на последних символах, а стоп-символ текста подсказывает, на сколько можно сдвинуться: если стоп-символа нет в образце — прыгнуть сразу на `m`, если есть — совместить с его самым правым (кроме последней позиции) вхождением. На больших алфавитах среднее число сравнений подлинейное: алгоритм часто вообще не смотрит большинство символов текста. Плата — таблица сдвигов на алфавит и отсутствие гарантии: на периодических текстах (например, текст `aaa…a`, образец `ba…a`) сдвиги малы и поиск вырождается до `O(n·m)`.

```text
БМ_ХОРСПУЛ(T, P):
    для каждого символа c: сдвиг[c] ← m
    для i от 0 до m - 2:            # последний символ образца не учитывается
        сдвиг[P[i]] ← m - 1 - i
    start ← 0
    пока start ≤ n - m:
        k ← m - 1
        пока k ≥ 0 и T[start + k] = P[k]:
            k ← k - 1               # сравнение справа налево
        если k < 0:
            вхождение на start
            start ← start + m       # образец совпал целиком
        иначе:
            start ← start + сдвиг[T[start + m - 1]]
```

Полный Бойер — Мур добавляет эвристику хорошего суффикса (учёт совпавшего суффикса, аналогичный границам КМП) и тогда лучше работает на периодических текстах, но остаётся сложнее в реализации.

### Рабин — Карп

Считает хеш образца и скользящий хеш каждого окна текста длины `m`; полиномиальный хеш пересчитывается за `O(1)` при сдвиге окна на один символ. Позиция проверяется посимвольно **только** при равенстве хешей. В среднем это `O(n + m)`; в худшем случае (все хеши совпадают) — `O(n·m)`. Выигрывает там, где посимвольное сравнение дорого или нужно искать много разных образцов одной длины (их хеши можно собрать в хеш-таблицу), и лежит в основе практических методов проверки плагиата и поиска заимствований.

```text
РАБИН_КАРП(T, P):
    hp ← хеш(P);  ht ← хеш(T[0..m-1])
    для start от 0 до n - m:
        если ht = hp и T[start..start+m-1] = P:   # сравнение только при равенстве хешей
            вхождение на start
        если start < n - m:
            ht ← ( (ht - T[start]·B^(m-1)) · B + T[start + m] ) mod M
```

### Ахо — Корасик

Строит по всем образцам бор и добавляет суффиксные ссылки — пути к наибольшему суффиксу каждой вершины, который тоже есть в боре. Затем делает **один** проход по тексту: в каждой вершине автомат отмечает все образцы, оканчивающиеся в текущей позиции (сама вершина и цепочка суффиксных ссылок). Это оптимальный выбор для поиска сразу многих образцов (словарь запретных слов, антивирусные сигнатуры): время `O(n + m + z)`, где `z` — число ответов, память `O(m·σ)` (меньше, если хранить переходы в хеш-таблице).

```text
АХО_КОРАСИК(T, набор образцов):
    бор ← пустой;  добавить в бор все образцы
    для каждой вершины v: link[v] ← наибольший собственный суффикс v, лежащий в боре
    v ← корень
    для i от 0 до n - 1:
        пока из v нет перехода по T[i] и v ≠ корень:
            v ← link[v]
        если есть переход: v ← переход(T[i])
        для u ← v; u ≠ корень; u ← link[u]:
            если u — конец образца: вхождение образца, кончающегося на i
```

Коротко о выборе: один образец и гарантии на любых данных — КМП; длинный образец и «хороший» алфавит — Бойер — Мур; много образцов — Ахо — Корасик (или Рабин — Карп с хеш-таблицей образцов); простота важнее скорости — наивный.

## Ответы на контрольные вопросы

**1. Что такое строка, её префикс и суффикс?**

Строка — конечная последовательность символов некоторого алфавита. Префикс строки `s` длины `k` — строка `s[0..k-1]` (первые `k` символов), суффикс — последние `k` символов `s[n-k..n-1]`. Префикс (суффикс) называется собственным, если он не совпадает со всей строкой, то есть `0 ≤ k < n`. Пример для `s = ababa`: собственные префиксы — `a`, `ab`, `aba`, `abab`; собственные суффиксы — `a`, `ba`, `aba`, `bab`. Границей строки называют строку, являющуюся одновременно её собственным префиксом и собственным суффиксом: у `ababa` границы `a` и `aba`.

**2. Идея наивного поиска и его сложность.**

Образец прикладывается к каждой допустимой позиции текста `start = 0 … n−m` и посимвольно сравнивается слева направо; при первом несовпадении проверка прекращается, а позиция сдвигается на единицу. Сложность по времени — `O((n−m+1)·m)` в худшем случае (например, текст `aaaa…a`, образец `aa…ab`: почти каждая позиция проверяется целиком), лучший случай — `O(n)` (несовпадение на первом символе). Дополнительная память — `O(1)`.

**3. Два основных направления оптимизации наивного алгоритма.**

Первое — **сдвигать образец на несколько символов сразу**, извлекая информацию из несовпадения: алгоритмы Бойера — Мура по стоп-символу и совпавшему суффиксу в среднем пропускают участки текста целиком (до подлинейного `n/m` сравнений). Второе — **не повторять уже выполненные сравнения**: префикс-функция в КМП (или детерминированный автомат) знает наибольшую границу совпавшей части, поэтому текстовый указатель никогда не отступает и общее число сравнений гарантированно `O(n + m)`. Дополнительные приёмы той же природы — предобработка образца (таблицы сдвигов, π-функция) и грубая фильтрация позиций хешем (Рабин — Карп).

**4. В чём идея поиска образца алгоритмом Бойера — Мура?**

Сравнение выполняется **с конца образца** (справа налево). При несовпадении применяются две эвристики, и сдвиг выбирается как максимум: эвристика плохого символа — сдвинуть образец так, чтобы несовпавший символ текста оказался напротив своего самого правого вхождения в образец (или ушёл за него, если символа там нет); эвристика хорошего суффикса — учесть уже совпавший суффикс и сместить образец к его ближайшему повторению (или к префиксу, совпадающему с его частью). Благодаря большим сдвигам алгоритм в среднем просматривает лишь малую долю текста.

**5. Асимптотическая сложность Бойера — Мура по времени и памяти.**

Предобработка — `O(m + σ)` времени и памяти. Худшее время: `O(n·m)` для версии только с эвристикой плохого символа (периодический текст); полный алгоритм с обеими эвристиками делает не более `O(n + m)` сравнений в худшем случае (оценка ≈ `3n`). Лучший/средний случай — подлинейный, около `n/m` сравнений на символ текста. Память — `O(σ + m)`: таблица стоп-символов на алфавит плюс таблицы границ суффиксов.

**6. Как влияет размер таблицы кодов в БМ на скорость поиска?**

Таблица стоп-символов хранит сдвиг для каждого символа алфавита. Полная таблица на весь алфавит даёт `O(1)` доступ и максимальную скорость, но занимает `O(σ)` памяти — для больших алфавитов (Unicode) это расточительно. Компактные варианты (только символы образца в хеш-таблице/словаре, ограниченный диапазон кодов) экономят память, но каждый промах таблицы требует отдельной обработки (сдвиг на `m` как для отсутствующего символа) и может замедлить доступ константным множителем. С асимптотической точки зрения скорость от размера таблицы не зависит — сказываются только константы; слишком маленькая таблица на «богатом» алфавите ухудшает качество эвристики стоп-символа, а раздутая — локальность кэша.

**7. За счёт чего БМ оптимален в большинстве случаев?**

За счёт больших сдвигов и проверки с конца. Во-первых, несовпадение обычно обнаруживается на последних символах образца, то есть дёшево; во-вторых, стоп-символ текста чаще всего либо отсутствует в образце (сдвиг на всю длину `m`), либо стоит в нём далеко от конца. В результате за один шаг алгоритм в среднем пропускает `m` символов текста и делает порядка `n/m` сравнений — подлинейное среднее время, когда большая часть текста вообще не читается. Ни один алгоритм не может сделать меньше `n/m` проверок позиций, поэтому БМ считается практически оптимальным для длинных образцов и больших алфавитов.

**8. Влияние префикс-функции в КМП на поиск; пример.**

Префикс-функция `π` образца заранее кодирует все его границы: `π[i]` — длина наибольшего собственного префикса, совпадающего с суффиксом `p[0..i]`. Когда при поиске не совпадает `p[j]`, известно, что предыдущие `j` символов текста совпали с образцом; заменив совпавшую часть на её наибольшую границу `j ← π[j−1]`, КМП продолжает сравнение с того же символа текста. Текстовый указатель не отступает, уже проверенная информация не выбрасывается, каждый символ текста сравнивается в `O(1)` амортизированном числе операций, суммарно `O(n + m)`. Пример: `π(abacaba) = [0, 0, 1, 0, 1, 2, 3]`, `π(aaab) = [0, 1, 2, 0]`. В работе `π` используется и после нахождения вхождения (`j ← π[m−1]`), что позволяет за один проход найти последнее из перекрывающихся вхождений.

**9. Пример строки, где поиск `aaabaaa` эффективнее КМП, чем БМ, и наоборот.**

Оба примера проверены подсчётом сравнений. КМП эффективнее на тексте из одних букв `a` (например, 24 символа `a`), образец `aaabaaa`: стоп-символ текста всегда `a`, а самое правое вхождение `a` вне последней позиции стоит в образце у самого конца, поэтому сдвиг Хорспула всегда равен 1 и каждое из 18 выравниваний даёт 4 сравнения — всего 72; КМП благодаря префикс-функции делает 45 сравнений (порядка `2n`). БМ эффективнее на тексте из символов, отсутствующих в образце (например, 24 символа `c`), тот же образец: первое же сравнение не совпадает, сдвиг равен всей длине `m = 7`, всего 3 сравнения; КМП же честно сравнивает все 24 символа текста.

**10. В чём идея поиска образца алгоритмом Рабина — Карпа?**

Позиции фильтруются хеш-функцией: вычисляется хеш образца и хеши всех окон текста длины `m`, причём используется полиномиальный **скользящий** хеш — при сдвиге окна на один символ новый хеш получается из старого за `O(1)` (вычесть вклад уходящего символа, домножить на основание, добавить входящий). Окно с совпавшим хешем проверяется посимвольно, чтобы исключить коллизии. Тем самым дорогая проверка выполняется только для «подозрительных» позиций, а среднее время — `O(n + m)`; алгоритм естественно обобщается на поиск многих образцов одной длины через хеш-таблицу их хешей.

**11. Асимптотическая сложность Рабина — Карпа.**

Предобработка и вычисление хешей — `O(n + m)`. Среднее и ожидаемое время (при хорошей хеш-функции и малом числе коллизий) — `O(n + m)`; дополнительная память — `O(1)`. Худший случай — все `n − m + 1` окон дают ложные совпадения хешей и каждое проверяется посимвольно: `O(n·m)`. Модульную арифметику берут в машинных целых (хеш по модулю `2^64` или простому модулю), чтобы переполнение не портило результат.

**12. Идея алгоритма Ахо — Корасика, вычислительная и ёмкостная сложность.**

Ахо — Корасик ищет **все** вхождения **всех** образцов из заданного множества за один проход текста. По образцам строится бор, к которому добавляются суффиксные ссылки: для каждой вершины — ссылка на наибольший её суффикс, присутствующий в боре (функция переходов доопределяется так, что автомат из любой вершины по любому символу имеет ровно один переход). При чтении очередного символа текста состояние автомата меняется за `O(1)` амортизированно, а все образцы, оканчивающиеся в текущей позиции, собираются проходом по цепочке суффиксных ссылок. Вычислительная сложность — `O(m)` предобработка и `O(n + m + z)` на поиск (`z` — суммарное число ответов; для перечисления всех вхождений это оптимально), ёмкостная — `O(m·σ)` для бора с полными переходами либо `O(m)` при хранении переходов в словарях (тогда переход ищется за `O(log σ)`).
